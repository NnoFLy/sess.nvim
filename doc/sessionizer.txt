==============================================================================
INTRODUCTION                                                     *sess.nvim*

sess.nvim manages sessions on the latest stable Neovim release only. Older
versions and nightly are unsupported. Telescope/plenary are optional.

Quick start: >
    require("sess").setup()
    vim.keymap.set("n", "<M-s>s", "<cmd>Sess save<cr>")
    vim.keymap.set("n", "<M-s>l", "<cmd>Sess list<cr>")
<
==============================================================================
CONFIGURATION                                      *sess-setup* *sess.setup*

setup() returns (ok, err) and logs failures. Call once. Unknown options fail. >
    require("sess").setup({
        paths = {}, -- picker directories/glob patterns
        smart_auto_load = "current", -- current | all | none
        auto_save = true,
        exclude_filetypes = { "gitcommit" },
        log_level = "info", -- debug | info | warn | error
        store_path = vim.fn.stdpath("data") .. "/sess.nvim",
        hooks = {},
        keymap = {
            prefix = "<C-q>",
            set_mark = "<C-q>",
            edit_marks = "<C-e>",
        },
        mark_window = {
            position = "right_bottom",
            width = 48,
            height = 10,
            margin = 1,
            border = "rounded",
            title = " Marks ",
            title_pos = "center",
            win_options = {
                cursorline = true,
                winblend = 0,
                winhighlight = "",
            },
            keymap = {
                load_prefix = "g",
                delete = "d",
                undo = "u",
                change_mark = "r",
                rename = "R",
            },
        },
        tabline = { enabled = true },
        sidebar = {
            enabled = true,
            start_open = false,
            position = "left", -- left | right
            width = 32,
            min_width = 24,
            max_width = 48,
            active_expand = "all", -- all | current | none
            toggle_key = false,
            refresh_interval = 1000,
            mouse = true,
        },
    })
<
smart_auto_load accepts only "none", "current", or "all". Omitted/nil uses
"current"; booleans and unsupported values are errors (no compatibility aliases).

  current   Load the exact normalized startup cwd identity (realpath where
            available); no parent/project-root search. Create only after a
            successful lookup with no match AND an empty startup editor. With
            meaningful unmanaged state, no match succeeds without creating or
            changing anything. Ambiguity, failed lookup, corrupt
            catalog entries preventing uniqueness checks, or failed load is
            reported without replacement creation.
  all       Resume the previous managed instance's active set, not every saved
            session. See |sess-resume|.
  none      Disable automatic startup loading/creation, not exit bookkeeping.

auto_save snapshots only the current session on exit, unless the current
filetype is excluded. None of these options writes modified files to disk.

Both loading modes require setup before VimEnter and implicit launch intent.
Files/directories, stdin (including StdinReadPre), -S scripts/sessions, -c commands,
+cmd, and --cmd disqualify startup. Option operands are interpreted by role; a
config/log/shada path beginning '+' is not a command. A terminal -- with no file
is allowed. Late setup never performs catch-up loading. Existing native sessions
or an already-started sess.nvim session also suppress automatic restoration.

Plugin-created buffers (including modified named/unnamed, scratch/nofile and
terminal buffers), splits, tabs, floats, local cwd scopes and view changes do NOT
suppress restoration. Launch intent/session membership is rechecked immediately
before the one deferred attempt. Typed input observed by vim.on_key() from setup
to that attempt cancels it; programmatic buffer/window changes and non-typed
feedkeys do not. This uses Neovim's typed-input provenance, not changedticks or
hardware identity: nvim_input() and feedkeys with the 't' flag also count as typed
input. Input listeners are removed on cancellation, dispatch, or reconfiguration.
Managed registrations invalidate older scheduled tokens; public setup() still
rejects repeated setup. There is no retry or late catch-up.

The restored session owns the visible layout. Displaced startup buffers retain
live IDs, contents and terminal jobs, but become unlisted and are not implicitly
owned or saved by the restored sessions. Use :ls! and :buffer N to recover them;
ordinary buffer pickers may omit unlisted buffers. A snapshot's explicit reference
to the same file can reuse its live buffer, retaining unsaved contents. Explicitly
displaying a buffer in a session can make it part of that session's live view.
The old startup layout is not retained after success or kept as a separate active
context. Protection covers bufhidden=wipe/delete/unload and disables autowrite
during transitions, including buffers created in the adapter's callback drain.
No modified files are written just to restore a session. Missing/unusable history
leaves startup state untouched; a failed load attempts to restore its pre-transition
live layout.
Arbitrary sourced Vimscript or autocmd effects during any transition cannot be
fully rolled back. This includes deletion, stopped jobs, writes, and callbacks
that override lifetime protection (for example, resetting bufhidden to wipe
inside BufLeave). Such callbacks can still destroy buffers or jobs.
UI2 source-window repair remains internal to the editor adapter, including on
source failure; no plugin allowlist controls startup eligibility.

Empty-only unmatched creation requires one ordinary window/tab, no local cwd
scopes, and empty unnamed unmodified normal buffers (extra hidden buffers must
also be unlisted). Editor-owned UI2 presentation is ignored for this test. This
stricter creation check never blocks restoration of an existing session.

The reserved SessNvimInternal augroup is used for sess.nvim's managed
autocommands. Use a different augroup for user autocommands.

==============================================================================
RESUME                                                         *sess-resume*

Each store has one version-1 data-only resume.json with ordered active_ids and
an optional current_id belonging to that set. IDs are validated before filesystem
use; targets are resolved through the catalog. It contains no executable code,
snapshot paths, or snapshot contents. Missing or intentionally empty history is
a no-op in all mode. Malformed/incompatible/unsafe history is reported, never
silently repaired, deleted, or replaced with cwd loading.

All mode preflights metadata, cwd and snapshot availability/structure. Unusable
entries are skipped with diagnostics, without creating replacements. Survivors
load in recorded order except that the recorded current session loads last. If
it is unavailable (or absent), the first survivor in recorded order loads last
as the deterministic selection. Active order is preserved separately, including
partial progress. With no survivors, startup stays untouched.

Restoration uses ordinary lifecycle loads: outgoing saves, before hooks, commit,
after hooks and User events, under one recursion guard. Each target is revalidated
at execution. A before-hook, execution, editor-transition, or persistence failure
stops further restoration and retains earlier commits; ordinary per-transition
rollback protects reversible editor state. Post-operation hooks and subscribers
see committed state; their failures are nonfatal diagnostics and do not halt
restoration. Arbitrary sourced code and callback effects cannot be rolled back.

On normal exit, an instance that has managed any session publishes its whole
active set and selection, even in none/current modes or with autosave disabled.
A never-managed instance leaves history untouched. Intentionally unloading all
sessions publishes an empty set. No inactive snapshots are forcibly saved.
Required current-session autosave must succeed before publication; excluded
filetypes and auto_save=false skip that save, but still publish membership.
Write/save failures are reported and preserve the previous resume document;
metadata warnings can accompany a successful save/publication. Exit diagnostics
are emitted synchronously so they are not lost when the process terminates.
Hooks and User events are suppressed during actual exit saves.

The last successful managed normal exit atomically replaces the whole record;
instances neither merge memberships nor read/modify/write a shared active set.
There is no transaction across snapshots and the resume document. Retaining an
old document does not revert snapshots already saved by this or another editor.
Resume refers to ordinary mutable snapshots, not immutable historical versions,
and does not resurrect live processes, runtime agents, or jobs. Fidelity remains
limited by Neovim's session capabilities/options. Keep the store private: resume
data cannot choose arbitrary snapshot paths, but normal Vim session snapshots
execute code under the existing trusted-store model, not a sandbox.

Automation API (used by managed startup/exit adapters): >
    local api = require("sess.api")
    local ok, err, result, diagnostics = api.resume.startup(mode)
    local ok, err, record, diagnostics = api.resume.exit()
<
Both require setup() and hold one lifecycle operation scope through observers;
recursive mutations fail. startup(mode) defaults to configured smart_auto_load.
The editor/event adapter owns eligibility checks; calling startup() directly is
not a substitute for launch-intent/input checks. The lifecycle preserves displaced
unmanaged buffers and applies empty-only unmatched creation even for direct calls.
result contains restored_ids in recorded order, current_id, and
failed_id on an execution-time failure. Errors may return partial committed
results and diagnostics; missing/empty history succeeds with no restored IDs.
exit() uses configured autosave/filetype policy and returns the attempted record,
or nil when never managed or when a required save fails. The managed adapter may
pass its captured setup options to exit(options). Neither call logs directly;
managed adapters report errors separately from diagnostics. Boundary/setup or
unexpected exception failures may return only (false, err).

COMMANDS                                                     *sess-commands*

:Sess create [path]                                          *:Sess-create*
    Create and enter a session. If one exists for the path, load it instead.
    With no path, use current cwd.

:Sess load [target]                                          *:Sess-load*
    Load by id/name/path/@mark. Path targets, including the current cwd, load
    an existing session or create one. Invalid or missing directories are
    rejected. With no target, use current cwd. Mark targets are resolved
    through the normal load lifecycle.

:Sess mark @mark [target]                                     *:Sess-mark*
    Assign a persistent one-character lowercase ASCII letter or digit mark.
    The default target is the current session. Replacing an existing mark
    requires confirmation in the command or picker UI; the API is prompt-free.

:Sess unmark @mark                                           *:Sess-unmark*
    Remove a mark. Stale marks remain until explicitly unmarked or replaced.

:Sess save                                                   *:Sess-save*
    Snapshot only the current session. No arguments; no implicit creation.

:Sess term [command]                                         *:Sess-term*
    Launch a persistent interactive shell (no arguments), or execute the raw
    command text through 'shell' with -c. Quoting, pipes and redirects are
    preserved. Use the invoking window's effective cwd, including lcd/tcd.
    The current session is the optional owner; without one, create unassigned
    work, not a session. Requires external tmux. See |sess-terminal|.

:Sess last                                                   *:Sess-last*
    Load the previous session. When no in-memory previous session exists,
    such as after a fresh start, load the most recently used session other
    than the current session.

:Sess unload [target]                                        *:Sess-unload*
    Unload by id/name/path; default current. Close exclusive buffers and their
    ordinary terminal jobs, forget the live view, and remove from active
    sessions. Managed terminal attachments detach without stopping execution.
    Ask Save/Discard/Cancel for unsaved buffers, then Stop/Cancel for ordinary
    live jobs.
    Cancel either prompt to abort before writes or teardown. Shared buffers and
    unrelated jobs stay alive. Retain the snapshot. Inactive targets are a no-op.

:Sess pin [target]                                           *:Sess-pin*
    Toggle pin. Default target is current.

:Sess rename [target] [name]                                 *:Sess-rename*
    Rename the target (default current); prompt for a missing name.

:Sess delete [target]                                        *:Sess-delete*
    Move the target (default current) to private trash. Buffers/jobs are never
    deleted/stopped. Refuse owners with persistent terminals or incomplete
    associations until explicit stop/delete controls are available.

:Sess restore [target]                                       *:Sess-restore*
    Restore a deleted session by name, id, or trash key. Without a target,
    open the deleted-session Telescope picker. Restore never loads or changes
    editor state. Completion offers names, ids and keys.

:Sess list                                                   *:Sess-list*
    Open the Telescope picker.

:Sess active                                                 *:Sess-active*
    Open the active-session dashboard. All Sess pickers display results
    top-to-bottom with the input prompt at the top. Regular session rows use
    ● current, ○ active, · inactive, and + new directory state markers. ◆ marks
    the previous session, and ★ marks pinned regular rows. Marks, names and
    paths stay aligned. The current session is omitted from the regular picker.
    Detailed regular rows also show relative last-used time and session age;
    agent summaries are not shown there. Active session headers omit the pinned
    column. Active sessions are tree-style groups with distinct headers and
    agent rows; the title and headers include compact session/agent counts.
    Sessions start collapsed.
    Configure Telescope's active_expand option as "all", "current", or "none"
    to change the initial expansion. <Tab> expands/collapses the selected
    group; <S-Tab> expands/collapses all groups; <Enter> switches and focuses.
    Each active session header ends with counts such as "agents: 1 working · 2 idle";
    loading and stale probes are shown explicitly. Current headers, focused
    agents, blocked/unknown statuses, and stale data have distinct visual
    treatment. Empty expanded groups show only their session header. <C-b> prompts
    for a mark on the selected session. Marks appear on active session headers and
    regular picker rows. Known agent commands
    running in terminal buffers (including pi, codex, claude, and opencode) are
    detected (excluding managed persistent-terminal attachment views);
    integrations may still register those buffers explicitly. Enter loads
    the parent and focuses the selected agent's existing visible buffer.
    Persistent terminals appear beneath active owners, without duplicate execution
    identities. A final expandable Background terminals group contains inactive
    owners' and unassigned terminals and shows owner names (or owner IDs if the
    name is unavailable). Inventory alone never activates a session. Terminal
    running/completed/unknown state is not agent working/idle/blocked/done status.
    Enter on a terminal calls |sess-api.terminal.focus|; Enter on the background
    header only expands (no-op if already expanded). Session mutations are
    unavailable on both. Status refresh is best-effort: a failed probe leaves the last rows usable and emits
    a diagnostic, while a selected agent that disappears falls back to its
    parent session. The last completed snapshot is cached in memory, so reopening
    the picker shows known agents immediately. A lazy refresh reconciles live data
    and marks cached rows stale until it completes. Header arrows indicate
    expansion state, and summaries use text as well as symbols for loading, stale,
    blocked, and unknown data. By default `<C-r>` manually refreshes agent data
    when unclaimed by another active mapping; configure `active.refresh_key` with
    another key
    or `false` to disable it. With `active.header_navigation` enabled (default),
    `<C-j>` and `<C-k>` move to the next and previous group headers. Configure
    `next_header_key` and `previous_header_key`, or set header navigation to
    false. Existing active mappings always win. Refresh preserves prompt,
    selection, expansion, and the last usable snapshot; failed probes expose a
    textual warning. Opening/refreshing the picker never launches commands or
    persists agent state; accepting a terminal may reconnect an attachment view.

:Sess sidebar                                               *:Sess-sidebar*
    Toggle the optional native active-session sidebar. It polls only while
    open and preserves selection and expansion across refreshes and tab
    changes. Refresh does not snap the cursor back into session/agent rows
    when it is on the title, separators, or footer.
    Session actions require the cursor on a real session or agent row, never
    a remembered selection on title/separator/footer lines. Agent
    rows target their parent for session operations. Confirmations identify
    the target. Session-only actions cannot target terminals or the background
    header. View-wide actions work anywhere.

    sidebar.enabled enables the command; sidebar.start_open opens it after
    setup. position is left or right; width is clamped to min_width, max_width,
    and available editor space. active_expand is all (default), current, or none.
    The selected expansion policy also applies to sessions added while open;
    refresh preserves manual expansion choices.
    Expanded sessions without agents or terminals show only their session header.
    Terminals are grouped as in :Sess active, with Background terminals last.
    all expands the background group too; current/none leave it collapsed.
    toggle_key is false or an unclaimed normal-mode key, and refresh_interval
    is a positive integer in milliseconds.

    Fixed buffer-local normal-mode mappings (no keymap configuration):
      <CR>            Load session, then focus selected agent; on a header,
                      focus its remembered agent if present. On a terminal,
                      safely focus/reconnect it; on Background terminals, expand
                      only (already expanded is a no-op).
      <Tab>           Toggle containing group expansion (including terminals).
      <S-Tab>         Collapse all if ANY expanded; otherwise expand all.
      <C-j>/<C-k>     Next/previous group header, wrapping.
      r / <C-r>       Refresh (r waits briefly because it also prefixes rr).
      rr              Rename selected session/parent; blank input cancels.
      uu              Safely unload selected session/parent using shared
                      Save/Discard/Cancel and Stop/Cancel confirmations.
      dd              Confirm deletion of selected session/parent; default No.
                      Removes stored session, not live buffers/jobs.
      <C-b>           Assign mark (a-z, 0-9); confirm replacing an owner.
      um              Clear parent's assigned mark; no-op when none.
      p               Toggle parent's pin (shown only on sidebar headers).
      <C-y>           Copy full parent cwd to + register; report clipboard errors.
      <C-o>           Focus selected agent WITHOUT switching; current session
                      only, not a session-header action.
      <C-s>           Cycle default -> recent -> pinned -> activity -> name
                      -> default using shared picker sorting.
      ?               Temporary, scrollable native help listing ALL actions.
                      Available actions come first; unavailable actions are
                      dimmed and grouped under a ▸ heading for each shared
                      reason, including disabled mouse actions.
      q / <Esc>       Close sidebar; in help, dismiss and restore origin focus
                      without changing sidebar selection or view.
    When mouse is true, a click selects and a double-click accepts; the global
    'mouse' option is not changed. Pending prompts block conflicting actions
    and refresh. Late callbacks after close/reopen or a vanished target cannot
    mutate the old selection. Errors are reported separately from successful
    diagnostics; cancellation preserves live state and sidebar visibility.

    Sort is sidebar-local: preserved while open/across refresh and reset on
    close/reopen. The footer shows `sort: <state>`, a blank line, then
    `? - Help`. Failed redraw retains the previous mode/view. Pins use the existing icon/ASCII fallback; Telescope
    headers are unchanged. The sidebar does not require Telescope or provide
    search/filter, create, restore-deleted or density controls.

    Sidebar and help buffers/windows are transient UI. The editor adapter excludes
    them from captured and persisted session state, layout/current-window
    restore, and resource cleanup. The logical sidebar follows the current
    tab without leaving a background-tab window. Session transitions retain
    it across committed or rolled-back editor changes; refresh failures do
    not discard live buffers or jobs.

NATIVE TABLINE                                               *sess-tabline*

    setup() defaults to tabline = { enabled = true }. It decorates an existing
    custom native tabline, or supplies Sess's clickable tab list when 'tabline'
    is empty. To disable both the UI and decoration: >lua
        require("sess").setup({ tabline = { enabled = false } })
<
    tabline must be a table with enabled as its only option; enabled must be
    boolean. Unknown nested keys (including ui) are rejected before editor
    options, storage or mappings change. setup() is one-shot, not a runtime toggle.
    enabled=false leaves both 'tabline' and 'showtabline' untouched.
    'showtabline' is always preserved:
        0   Tabline hidden; sidebar keeps its in-buffer heading.
        1   Tabline visible only with multiple tabs; one tab keeps that heading.
        2   Tabline always visible.
    Sess's own UI shows each tab's number and safe filename label, uses native
    tab-number click targets, and highlights the selected tab.
    This UI replaces Neovim's internal default, not an existing custom provider.
    Closing the sidebar leaves the supplied tab list in place.

    An existing nonempty native format or top-level %! expression is wrapped
    without flattening its output. Original click/callback targets, highlights,
    groups, alignment and truncation remain native format directives. A %! provider
    is evaluated once per render in the original current-window context; its
    FORMAT result is decorated, then Neovim evaluates any %{} items natively.
    Closing the sidebar returns that format unchanged. A provider installed later
    owns the option; it is never automatically adopted or rewrapped.

    Executable configuration keeps Neovim's sandbox restrictions. Sandboxed
    options fall back to their original format; restoration of the original
    option is deferred outside textlock and emits one warning. A first render
    delayed until after setup is reconciled at the next SafeState (idle) event.
    Raw script-local s: or <SID> references in expressions are left untouched
    with a warning, since their ambient script context cannot be retained reliably.
    Use explicit <SNR> references instead. Quoted text is not rewritten. A failing
    provider retains Neovim's native error/reset behavior and restores the sidebar
    heading; initial rendering failures are also reported as a warning without
    aborting setup. Sess never evaluates captured executable strings through
    trusted Lua.

    Replacing 'tabline' suspends heading integration; restoring the installed
    expression permits it again. Hidden, unsupported or external UI tablines
    (ext_tabline) keep the in-buffer sidebar heading. No tabline plugin is required.
    Third-party provider configuration is not changed.

    Low-level helpers in require("sess.ui.tabline") remain available:

    setup(expression_or_false) -> true | false, error
        Registers the exact non-empty native 'tabline' expression whose renderer
        calls render(). false disables the offset. Invalid arguments return
        false and an error without changing the registration. Does NOT change
        'tabline', 'showtabline', or any provider. Replacing 'tabline'
        suspends the offset; restoring the registered expression allows it
        again. External UI tablines (ext_tabline) are not integrated.

    label(tabpage?) -> string
        Accepts a Neovim tabpage handle, NOT a tab number; defaults to current.
        Returns its focused non-floating, non-transient editing window's buffer
        basename. While sidebar/help/other transient UI is focused, uses the
        last-focused editing window/buffer pair if still valid in that tab;
        otherwise another valid editing window, then [No Name]. Invalid tab
        handles and unnamed buffers also yield [No Name]. Closed tabs are
        forgotten. Percent signs are doubled for safe insertion into native
        tabline format text; control bytes become spaces. Do not escape again.

    render(content) -> string
        content is trusted native tabline format text (not a label), including
        your own click targets and highlights. Returns it unchanged when
        disabled, hidden, replaced, externally drawn, or without an attached
        edge sidebar in the current tab. Otherwise reserves the sidebar's
        actual displayed left/right width and position for ACTIVE SESSIONS.
        The heading is truncated or padded to its display-cell width. A bounded
        native format group clips overflowing labels while preserving tab click
        and highlight directives. The heading has no tab click target.
        Content should describe tabs, not contain a second tabline expression.

    After render() first supplies the integrated heading for a registration,
    heading ownership remains with the visible integrated tabline across tab
    switches and resizing, without briefly restoring the in-buffer title.
    Buffer changes are deferred out of tabline evaluation; row selection,
    cursor mapping, and highlights follow the shifted rows.
    Hiding/disabling/replacing the tabline restores the in-buffer heading.
    With 'showtabline'=1 a single tab retains that heading; multiple tabs permit
    the offset. Closing/reopening, tab changes and resizing recompute geometry.
    Session capture and lifecycle behavior are unchanged. These helpers do not
    configure third-party tabline plugins.

Tab completion supports subcommands, marks, session names, deleted-session names/ids/keys,
create paths, and load directory paths. `load` accepts existing `@mark` targets;
`mark` completes valid marks and session targets independently. For load, path arguments beginning with
`~/`, `/`, `./`, or `../` complete immediate child directories; later arguments
are not completed. Command-line escaping is preserved. Corrupt trash records
are reported and skipped.

Agents are detected from live terminal jobs or registered through api.agent and
belong to active sessions only. Detection uses the terminal job command and,
where available, its process tree; it is best-effort and never starts or stops
processes. Managed persistent-terminal attachment views are excluded from automatic
agent detection; explicit buffer registrations remain valid. Known terminal agents
also inspect recent visible terminal output and
report idle, working, blocked, or unknown. The active picker polls and redraws
changed statuses while it is open. This screen detection is a fallback: an
explicit status supplied by an integration remains authoritative. The API
returns (ok, err, result, diagnostics); list is sorted by agent id and all
results are defensive copies. register, update, unregister, list, focus, and
focused do not write storage. `api.agent.explain(target, agent_id)` is a
read-only query returning (ok, err, explanation, diagnostics). The explanation
identifies the effective status source, bounded sanitized evidence, identity,
manifest and matched rule, screen summary, cache state, and diagnostics. The
error return is reserved for target/agent operation errors; probe and observation
failures remain non-fatal diagnostics in the fourth return value and in
explanation.diagnostics. Explanation results are defensive copies and do not
expose raw terminal output. `api.agent.report(target, agent_id, report)` and
`api.agent.release(target, agent_id, release)` are runtime-only integration APIs.
Reports require a bounded non-empty source, a non-negative integer sequence, and
idle/working/blocked/done/unknown status; optional info is bounded and ttl must be
positive and less than 24 hours (default 30 seconds). Reports apply only to live
targets and sequence ordering is independent per source. The most recently accepted
fresh source wins, with source name breaking an acceptance-time tie. Duplicate or
older reports/releases return an error without mutation. A fresh sequenced lifecycle
report is authoritative except that a high-confidence live screen blocker may
override a non-blocking (`idle`, `working`, or `done`) report; a blocker never
overrides a report already marked `blocked`. A release marks that source released,
lets screen detection resume, and retains its record for diagnostics and sequence
ordering. `explanation.integration` identifies the selected fresh record, or the
newest stale record when none is selected; it includes source, sequence,
acceptance/expiry, freshness, and release state. Expired or released reports are
diagnostic only. Reports never enter session snapshots or storage. Changing an
agent's buffer target clears its runtime reports and sequence state; other updates
preserve them. `unregister()` removes the agent and its runtime reports immediately.
`focus` operates only on the current session; a missing or hidden target is a
successful operation with an unavailable-target diagnostic. Agents are never restored
from disk.

The session Telescope picker normally shows available sessions. Search covers
names, working directories, marks, pinned/last labels, current/active state,
and agent name, status, and info. Each entry keeps the complete searchable
record in its ordinal for custom sorters. Name matches rank above path-only
matches; exact name and mark matches rank highest. Optional prefixes are `@a`,
`path:frontend`, `status:working`, and `agent:pi`; prefixes preserve spaces and
shell-like characters, and invalid syntax is treated as ordinary text. Configure
`search.fields`, `search.filters`, and `search.sort` (`default`, `recent`,
`pinned`, `activity`, or `name`) in the Telescope extension. The default order
is unchanged. Active agent matches keep their parent session visible. A custom
`sorter` receives the enriched ordinal. The status area can show practical
match counts (`show_count`, enabled by default), interpreted filters, and a
non-default sort mode (`show_sort`, enabled by default). Malformed filter-like
text remains ordinary search text. Set `cycle_sort` to `true` (using `<C-s>`),
a key string, or `{ i = "<key>", n = "<key>" }` to add an opt-in mapping in
insert and normal mode for regular and active pickers. Existing mappings in the
relevant mapping table take precedence and `false` disables a mode. Cycling
follows `default`, `recent`, `pinned`, `activity`, `name` and restores the
selected session, agent, or directory by stable identity.

<C-b> prompts
for and assigns a mark to the selected session. A prompt
beginning with `~/`, `/`, `./`, or `../` switches to immediate directory
completion and includes a `./` entry for the typed directory. Telescope path
mode also accepts fuzzy child-directory matches; command-line completion remains
prefix-based. In path mode, <Tab> inserts the selected directory with a trailing
slash and keeps the picker open. <Enter> loads or creates its session. Creating a session opens the default file
explorer in the project root. Returning to a non-path prompt restores the
normal picker.

==============================================================================
BUFFER AND CWD POLICY                                         *sess-buffers*

Switching saves the outgoing session, then hides its buffers. Named, unnamed,
modified, hidden and non-file buffers remain loaded. Terminal jobs keep running.
Switching never writes buffer contents, discards edits or deletes buffers.
This includes buffers with bufhidden=wipe/delete/unload: those options are
protected during transitions, then restored.

Returning to a still-active session restores its live buffer IDs,
layout, cursor positions, listing and cwd scopes rather than sourcing Vimscript
and restarting its terminals. Clean unnamed transition buffers are reused
rather than accumulated. This is not full workspace isolation: buffers are
shared; the same file in two sessions generally uses the same buffer. Window
IDs may change; not all window-local/plugin settings can be reconstructed.
User autocommands or trusted sourced code can still explicitly destroy state.

Live views, unsaved text and running jobs are process-local. After restarting
Neovim, only the persisted Vimscript snapshot is available. Unsaved text/jobs
cannot be recovered from it. Buffers displaced by startup restoration are
hidden/unlisted but remain manually accessible with :ls! and :buffer N; they
are not persisted in a separate startup session.

Active records track visited sessions except those explicitly unloaded/deleted.
Unloading wipes buffers owned only by the target session, stops their terminal
jobs and forgets the live view. Buffers shared with another session (or the
current editor) are retained. Ownership follows live views, not file paths.
Reloading an unloaded session sources its snapshot; terminal commands may start
again according to 'sessionoptions'. Deleting forgets the live view without
closing buffers/jobs; its SessUnloaded event is only a detachment notification.

Commands and Telescope offer Save/Discard/Cancel for modified exclusive buffers,
then Stop/Cancel for running terminal jobs, including idle shells. Cancel is the
default. Save asks for filenames for unnamed buffers; non-writable/plugin buffers
may refuse writes, aborting unload. No writes or teardown occur until both
confirmations are accepted. Unrelated background/plugin jobs are not tracked or
stopped: their session ownership cannot be reliably inferred.

Current unload snapshots the layout before closing it. Hidden-session unload
keeps the last snapshot without switching the current editor. Saving a newly
named hidden buffer writes its file, but does not add it to that old snapshot.

All saves use actual editor cwd scopes, without temporary chdir. Existing
directories are resolved with fs_realpath for project lookup, so symlinks share
one identity. Live views preserve global, tab-local and window-local cwd.
Disk snapshots follow Neovim's 'sessionoptions'.

LUA API                                                          *sess-api*

The API is prompt-free and does not notify. UI adapters own prompts/logging. >
    local api = require("sess.api")
    local ok, err, item, diagnostics = api.session.load("project")
<
Session mutation results: (ok, err, session, diagnostics). On success err is nil
and diagnostics is a list of strings. Restoration, metadata and observer
failures are diagnostics. A post-operation failure does not undo success.
Initialization and validation failures return false and an error, not exceptions.
Targets may be an id, name, path, or a record with id and metadata. Caller
metadata is never trusted as authoritative; records are reloaded from storage.

api.session.create(cwd?, opts?)                  *sess-api.session.create*
    Save outgoing session, hide buffers, enter a fresh session for cwd.
    opts: { name?, id?, hooks? }. Duplicate paths/names/ids fail before editor
    changes. Commands additionally load an existing session for the same path.
    Returns the created session and diagnostics; a lock-cleanup warning is
    reported once without turning an otherwise committed create into failure.

api.session.load(target?, opts?)                *sess-api.session.load*
    Default: lookup current cwd. opts: { hooks? }. Validate target, run pre-hook,
    revalidate, save outgoing session, restore destination, publish state.
    Same-session load succeeds without save/hooks/events; result four is {}.

api.session.last(opts?)                         *sess-api.session.last*
    Load the in-memory previous session. If none exists, load the most recently
    used persisted session other than the current session. opts: { hooks? }.
    The operation otherwise follows load(), including validation, hooks, saves,
    events and diagnostics.

api.session.save()                              *sess-api.session.save*
    Snapshot only the current session. Arguments, including nil, are rejected.

api.session.unload(target?, opts?)               *sess-api.session.unload*
    Default: current. opts: { hooks?, confirm? }. Close exclusive buffers/jobs
    and forget the live view. For current, snapshot before teardown, clear
    current and set previous to that session. For non-current, keep the last
    snapshot and leave current/previous/layout/cwd unchanged.
    Already inactive targets succeed without hooks/events. Missing targets fail;
    no current session is an error only when target is omitted.
    The older unload({ hooks = ... }) form still targets current.

    Without confirm, unsaved buffers or live terminal jobs cause an error before
    teardown. confirm(request) is called inside the mutation guard, with copies:
      request = { kind = "buffers"|"jobs", session, buffers }
      buffers contain { buf, name, modified, changedtick, terminal, job? }.
    For kind="buffers", return "save" or "discard". "save" may return a second
    value, { [bufnr] = filename }, required for modified unnamed buffers.
    For kind="jobs", return "stop". Any other result cancels the entire unload.
    Only exclusive resources needing consent appear in these requests. The
    buffers request precedes the jobs request. Both precede file writes.
    Commands and Telescope inject this callback; the core never prompts itself.
    Cancelling returns false, "unload cancelled". Write failures abort teardown.
    Managed terminal clients are attachments, not jobs requiring Stop consent;
    their execution survives teardown. Ordinary terminal consent is unchanged.

api.session.delete(target?, opts?)               *sess-api.session.delete*
    Default: current. opts: { hooks? }. Move persisted files to trash. Current
    deletion hides buffers and emits unload then delete. Non-current deletion
    does not perform an unload. No API confirmation prompt. Refuse deletion
    before hooks when persistent work/incomplete associations belong to this
    owner, or terminal registry safety cannot be established. Unassigned work
    alone does not protect unrelated owners.

api.session.list_deleted()                       *sess-api.session.list_deleted*

api.session.restore(target, opts?)               *sess-api.session.restore*

api.session.rename(target?, name)               *sess-api.session.rename*

api.session.toggle_pin(target?)                 *sess-api.session.toggle_pin*

api.session.get_by_mark(mark)                    *sess-api.session.get_by_mark*

api.session.list_marks()                         *sess-api.session.list_marks*

api.session.set_mark(target, mark, opts?)         *sess-api.session.set_mark*

PERSISTENT TERMINALS                                          *sess-terminal*

Install tmux separately and put its executable on PATH. Other session
operations and ordinary Neovim terminals do not require tmux. There is no
nonpersistent fallback if launch fails. 'shell' must name one executable, not
an executable plus shell arguments.

api.terminal.launch(command?)                    *sess-api.terminal.launch*
    Explicitly start one new execution and open its view in the current window.
    nil/omitted command starts an interactive shell (-i); a string runs through
    'shell' with -c. An empty string is an explicit empty command, not a shell.
    The command must be NUL-free and at most 32768 bytes. It is trusted shell
    input: only pass text you intend to execute. Use the invoking window's
    effective cwd, with window/tab/global scope. Resolve the current session as
    optional owner by stable ID. With no current session, launch unassigned
    work without creating or activating a session.

api.terminal.attach(id)                          *sess-api.terminal.attach*
    Open another view of an existing verified execution, including retained
    completed output. Never launch/restart the original command. id is the
    32-character lowercase hexadecimal execution ID returned by launch, not a
    buffer number, session name, tmux target, or synthetic buffer filename.
    Attach does not load an owner, change ownership, or activate a session.

api.terminal.list()                              *sess-api.terminal.list*
    Discover surviving executions created by launch, independently of runtime
    agent registrations or a prior Neovim instance. Validate the registry, server
    identity and associations; reused/unverified tmux targets are not adopted.
    This read-only query never launches stored commands or activates owners.
    Takes no arguments and requires setup(). Returns: >
        true, nil, entries, diagnostics
        false, error, retained_entries, diagnostics
<
    Each entry contains { id, owner_id?, owner_name?, name, execution_state,
    available }, with execution_state running, completed, or unknown.
    available is a boolean backend observation, not a promise focus will succeed.
    Missing/corrupt owners produce diagnostics; an owner ID remains actionable
    only through focus's ordinary owner validation. Backend failures preserve
    uncertain entries as unknown/unavailable, including entries from the last
    usable inventory. Successful per-entry backend observations remain intact on
    partial failure. Never treat a failed query as proof of closure/deletion.
    Inventory does not repair/delete the registry. Errors and nonfatal diagnostics
    remain separate.

api.terminal.focus(id)                           *sess-api.terminal.focus*
    Focus/reconnect one existing verified full execution ID, without launching
    its command. If owned, load the owner through the ordinary session lifecycle,
    including configured hooks, snapshot validation, safety and cancellation.
    Inactive owners are not bypassed, missing owners fail, and ownerless work
    opens without creating/activating a session or changing ownership. Revalidate
    identity after the load; reused/changed targets cannot redirect the view.
    Reuse a verified existing view, or reconnect when no usable view remains.
    Completed work opens read-only captured output with no terminal job.
    Captures over 64 KiB return an error without opening output; output is not
    truncated. Returns: >
        true, nil, { id, execution, bufnr, job_id? }, diagnostics
        false, error
<
    An owner load may already have committed before a later attachment or
    revalidation failure; failure never relaunches work or rolls back that load.
    Invalid IDs, unavailable/changed backend identity, missing/corrupt owners,
    cancelled/failed loads and view failures are errors. Successful owner-load
    diagnostics are included. It accepts no options or hook overrides.

Launch and attach require setup(), take at most one argument, and accept no
options or hook overrides. They return: >
    true, nil, { id, execution, bufnr, job_id }, diagnostics
    false, error
<
The success diagnostics result is a list of strings (possibly empty).
execution is a verified backend association with stable id, backend_id and
optional owner_id, plus backend identity/target fields. Treat those target
fields as observations, not authority to perform external destructive actions.
bufnr and job_id identify this editor's attachment, not the execution. Repeated
attach calls create independent buffers/jobs for the same execution ID. Each
launch creates a new execution ID even for identical command text.

Terminal operations share the lifecycle mutation guard, including during
session hooks and event subscribers. Launch/attach/list do not run
before_transition or after_operation, emit new User events, or publish session
runtime state. Focus uses ordinary owner-load hooks/events and commits session
state before observers; after-observer failures remain diagnostics. Existing
session hook/event ordering remains unchanged. Commands report API
errors and diagnostics through the usual UI adapter. A client that has already
exited during attachment startup produces an attachment error. Later unexpected
client failures and helper-cleanup failures are asynchronous warnings; they do
not change an earlier API result or mean execution completed. Intentional
wipe, unload and editor-exit detachment do not produce client-failure warnings.

Lifetime and layouts
    The plugin uses an isolated private tmux server/config/socket under the
    configured store's terminal directory, ignoring inherited TMUX/TMUX_PANE.
    Each owner has a tmux session with one window/pane per terminal;
    unassigned work has a separate owner group. One-window helper attachments
    link the original windows so changing the owner's selected window remotely
    cannot retarget another Neovim view. Views are ordinary terminal buffers,
    not tmux control-mode output; tmux status, prefix and mouse UI are
    disabled.

    Closing a view window, wiping its attachment buffer, switching/unloading
    sessions or exiting Neovim does not stop execution. An attachment's exit
    is separate from execution exit. Completed windows retain output for
    explicit attach. Rename preserves owner identity. Merely displaying an
    unassigned terminal in a session does not adopt it.

    Persistence means surviving editor exit while the backend and host remain
    alive. It does not promise reboot/backend-loss survival, and execution
    does not advance during host sleep. Direct external tmux termination is
    outside sess.nvim's confirmation UI.

    Snapshots contain inert sess-terminal:// references, never automatically
    replayable launch or attachment commands, even when sessionoptions
    includes terminal. Restoring a layout does not reconnect views yet:
    select a terminal in the sidebar/active picker or call focus(id) explicitly.
    attach(id) remains available without owner loading. Automatic view
    restoration, adoption of remote-created windows, remote collection and full
    stop/delete controls are deferred. Until those controls exist, owner deletion is refused for
    surviving work, including completed terminals and pending associations; it
    never silently orphans or stops work. Unassigned terminals do not block
    unrelated owner deletion. Ordinary terminal jobs retain their existing
    snapshot behavior and Stop confirmation on unload.

Failures and trust
    Missing tmux, invalid input, unsafe storage/config/socket, stale or reused
    backend targets, corrupt/incompatible registry data, backend creation and
    persistence failures return false and an error. No local-job fallback or
    implicit relaunch occurs. Existing live editor resources must be
    preserved. If execution committed but attachment fails, the error names
    the surviving execution ID: retry explicit attach(id), not
    launch(command).

    A failed/ambiguous creation or publication may leave a live execution and
    a pending association which cannot yet be attached. Pending records,
    failed publication temporaries, corrupt data and uncertain associations
    are preserved, never silently repaired, overwritten, deleted or retried to
    make launch succeed. These failures can also block owner deletion. A
    terminal registry lock is never automatically stolen. Persistence failures
    are errors even if external work already started; they do not imply
    rollback.

    Only explicit launch executes supplied shell text. Backend operations use
    structured argv and validated IDs/targets; discovered names, paths and
    metadata are not shell/tmux programs. Subprocess waits and captured
    output, command/registry/config sizes are bounded. Paths are handled
    literally, including tmux format-like text, but the store must remain
    private to the current user. Existing unsafe permissions/symlinks are
    rejected, not fixed. The private socket path must fit the portable
    100-byte tmux limit; choose a shorter store_path if necessary. Same-user
    access to this socket controls these processes; metadata validation is not
    a sandbox against that user. No network listener is added. These checks do
    not make arbitrary shell input safe or promise recovery after backend loss.

HOOKS AND EVENTS                                               *sess-hooks*

Supported hooks: >
    require("sess").setup({
        hooks = {
            before_transition = function(context) end,
            after_operation = function(context) end,
        },
    })
<
create/load/unload/delete accept per-call { hooks = {...} } overrides.
before_transition runs for create, load, unload, restore and current-session deletion.
Throw to abort. Its context contains { operation, session, current }, where
current is the outgoing session or nil. Preconditions are rechecked afterward.
Hooks may themselves change the editor; those changes are not transactional.

after_operation runs after successful create/load/save/unload/delete/restore/rename/pin/mark/unmark,
with committed state. Throwing only adds a diagnostic. Context records are
copies. The transition guard remains held through observers; recursive lifecycle and
agent mutations (including focus) return an in-progress error. Read-only
queries remain available.

User events:                                                   *sess-events*
    SessCreated SessLoaded SessSaved SessUnloaded SessDeleted SessRestored SessRenamed
    SessPinned SessMarked SessUnmarked

Payload event.data = { operation, session, current }. operation is lowercase
create/load/save/unload/delete/restore/rename/pin/mark/unmark. Mark events also
include mark and session_id; replacement includes previous_id. current may be nil,
and unmarking a stale mark may have a nil session. Each payload is
independent of owned runtime state.

Ordering: publish state, call after_operation, emit User event. Outgoing saves
emit SessSaved before destination operations. Create emits SessCreated, not
SessLoaded. Switching does not unload the outgoing session. Explicit unload
emits SessUnloaded. Current deletion emits SessUnloaded then SessDeleted;
non-current deletion emits only SessDeleted. Same-session load emits nothing.
During VimLeavePre autosave, persistence still runs but hooks and User events
are skipped because the editor is already shutting down.

Post-hook and subscriber errors never turn completed operations into failures.
Neovim may display subscriber errors itself; errors exposed through its API or
v:errmsg become diagnostics. Subscriber execution/continuation follows Neovim's
autocmd rules. Core code does not call vim.notify.

Example statusline/integration observation: >
    vim.api.nvim_create_autocmd("User", {
        pattern = { "SessLoaded", "SessCreated", "SessUnloaded", "SessRenamed" },
        callback = function(event)
            local current = event.data.current
            -- Or read vim.g.sess_current_session.
        end,
    })
<

PERSISTENCE, TRUST AND FAILURES                            *sess-persistence*

Session files execute trusted Vimscript. Never load a store writable by
untrusted users. Session directories have private 0700 permissions. IDs are
validated before path construction; editor file commands disable filename
expansion and command-bar parsing. Session file operations do not construct
shell commands. Explicit terminal launch runs user-supplied text through the
configured shell; tmux control operations use structured argv and validated
targets. See |sess-terminal| for that separate trust boundary.

Snapshots use unique sibling temporary files and atomic rename after mksession
succeeds. Generation/rename failure preserves the old snapshot and cleans up
temporary files. v:this_session uses the final path. Metadata is also replaced
atomically. Concurrent writers are last-write-wins without cross-process locks;
metadata lost updates remain possible. Snapshot and metadata are not one
filesystem transaction. Each temporary file is fsynced before replacement, but
the containing directory is not fsynced, so crash durability of the rename is
not promised. On Linux, Darwin and FreeBSD when /proc/self/fd or /dev/fd is available,
reads and writes walk opened storage-directory descriptors with
O_DIRECTORY|O_NOFOLLOW; regular-file reads add O_NOFOLLOW. Snapshot generation
writes through the securely-created descriptor itself, and loading executes
bytes read through that descriptor-relative boundary rather than reopening a
snapshot pathname. Other platforms, and restricted POSIX runtimes without
these primitives, remain compatible through a private-store pathname fallback.
It checks every existing storage component and rejects symlinked components, but
cannot prevent a concurrent pathname replacement between those checks. The
fallback makes no descriptor-level containment claim: keep the store private,
and operation-specific filesystem failures are returned by the affected
operation (as errors, or as diagnostics when the operation can complete) rather
than making setup unusable.

Before changing editor state, transitions validate metadata, target directories
and snapshots, then recheck after pre-hooks. State is published only after editor
success. Failed transitions attempt to restore windows, cwd scopes and buffer
listing; an outgoing save may already have completed. Cleanup errors are returned.
Arbitrary Vimscript/autocommands cannot be rolled back: sourcing failures may
leave partial editor changes. Post-save/load metadata failures are diagnostics
if the snapshot/editor change has already completed.

Unload rechecks buffer identity, modified text and live job IDs after consent
and before each deletion. Queued editor callbacks are drained before final
teardown checks. New resources or edits abort and require a retry. Terminal
output alone does not invalidate consent. File writes, wiped buffers and
stopped processes cannot be rolled back. A failed write can leave earlier files
saved; a teardown failure can leave some buffers/jobs already closed.
Remaining editor state is restored where possible; failure does not emit
SessUnloaded or remove the session from active records.

:checkhealth sess                                             *sess-health*
    Inspect setup, storage access, corruption, unsupported metadata versions
    and missing snapshots. Read-only: never sources, writes probes, repairs
    or deletes.

The active_expand option accepts "all", "current", or "none". The
poll_interval option sets the active picker polling interval in
milliseconds and must be a positive integer. Polling stops when the picker
closes. `active.refresh_key` is a non-empty key or false; it is generated only
when unclaimed by an active mapping. `active.header_navigation` enables the
conflict-safe next/previous header mappings, whose keys are configurable with
`next_header_key` and `previous_header_key` (each can also be false). Unsupported
values are rejected during Telescope setup. The optional display table accepts
mode "compact", "detailed", or "auto". Auto mode uses the actual Telescope
result-window width and changes to compact below compact_width (a positive
integer, default 100). `icons` and `ascii_fallback` are booleans; disabling
icons or enabling the fallback uses ASCII symbols. `toggle_key` is a
non-empty mapping key, false to disable the density mapping, or nil. A
configured regular-picker mapping at that key wins; mapping it to false also
disables the generated mapping. Invalid display types or values are rejected
during Telescope setup. The search table also accepts boolean `show_count` and
`show_sort`, plus `cycle_sort` as false, true, a key, or per-mode mapping.
The prompt contains only the `? - help` hint by default; search feedback settings
remain accepted for compatibility but are not rendered there.
The table also accepts show_metadata and show_agent_summary booleans, plus
path_style "full", "relative", or "short". show_metadata controls last-used
and age labels in regular detailed rows; show_agent_summary controls active
session header counts.
`highlights` overrides semantic Telescope highlight group names by field;
accepted fields include current, active, inactive, new, mark, name, cwd,
metadata, agent, working, idle, blocked, done, unknown, focused, and stale.
Rows measure the active Telescope result window in screen cells, retain complete
searchable ordinals, and recompute after terminal resize. Long paths shorten from
the middle and verbose active-agent info from the end without hiding state or
names.
At narrow widths secondary labels collapse to symbols or disappear, while tree
rows retain enough indentation for hierarchy. The preview uses `min_width`
(default 80) to hide itself when the result area is too small.
Regular session identity columns remain Unicode-safe with aligned
mark/name columns; active headers omit the pinned column. Default regular-picker
insert/normal mappings include `<C-y>` to copy the selected complete session
path. The active picker starts

switch/focus. Other active-only mappings, including refresh, focus-agent, and

`preview.width` as a fraction of the picker width. `preview.min_width` (default
80) hides it when the result area is too narrow. It is hidden on narrow

The active picker uses

DEVELOPMENT                                                *sess-development*

Run `sh tests/run.sh`. Set NVIM_BIN=/path/to/nvim to select a binary. Each case
uses a fresh process, temporary HOME/XDG/storage/fixtures and no user config,
plugins, ShaDa or swap. Temporary data is removed on exit. Telescope is not
required. Real tmux is required for terminal tests; absence is an explicit
failure, not a passing skip. Tests clean up only their own private servers,
including assertion failures. CI runs latest stable only.

Format changed Lua files with `stylua path/to/file.lua`; .stylua.toml defines
our style. Add --check to validate formatting without modifying files.
